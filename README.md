# ختم · Khatm

منصة فوترة إلكترونية متوافقة مع المرحلة الثانية من زاتكا (الربط والتكامل).
الاسم من «الختم» اللي بتحطه زاتكا على كل فاتورة مقبولة. اسم عمل — قبل اعتماده تجارياً لازم نتأكد من توفر النطاقات وبحث العلامة التجارية.

## البنية

```
packages/
  zatca/   مكتبة زاتكا: UBL 2.1، التجزئة (C14N 1.1)، التوقيع، QR، CSR، عميل API، معالج الربط
  db/      مخطط PostgreSQL (Drizzle) + ترحيلات + حمايات على مستوى القاعدة
  core/    إصدار الفاتورة (ICV/PIH بلا فجوات تحت التزامن) وإرسالها لزاتكا
apps/
  demo/    صفحة تجريبية بتشغّل المحرّك بالمتصفح (بدون سيرفر)
  (قادم)   تطبيق Next.js والـ Worker
scripts/   zatca-sdk.sh · setup-sdk.sh
tools/     zatca-sdk/ — حزمة SDK الرسمية (لا تُرفع للمستودع)
```

## التشغيل محلياً

```bash
pnpm install
docker compose -f docker-compose.dev.yml up -d   # Postgres 16 + Valkey
pnpm test
pnpm typecheck
```

### حزمة SDK الرسمية (للتحقق المحلي)

الاختبارات الأهم تمرّر كل فاتورة نولّدها على مدقّق زاتكا الرسمي (XSD + EN16931 + قواعد KSA + QR + التوقيع + PIH).
بدونه هالاختبارات بتتخطّى تلقائياً.

1. نزّل Java SDK من بوابة المطورين وفكّه في `tools/zatca-sdk`.
2. ثبّت **Java 11** (المنحنى secp256k1 انشال من Java 16 وطالع، فالتحقق من التوقيع بيفشل على النسخ الأحدث).
3. `scripts/setup-sdk.sh`

### الربط مع بيئة زاتكا التجريبية

```bash
pnpm --filter @khatm/zatca onboard --env sandbox
```

بيولّد مفتاح وCSR، بياخد شهادة امتثال برمز OTP الثابت للـ sandbox (`123345`)، بيمرّر فحوصات الامتثال الستة،
بياخد شهادة إنتاج، وبعدين بيعمل Clearance لفاتورة ضريبية وReporting لفاتورة مبسطة.
المفاتيح والأسرار بتنحفظ في `.zatca/` (مستثناة من git، صلاحيات 600).

للمحاكاة برقم ضريبي حقيقي: `--env simulation --otp <من بوابة فاتورة> --profile company.json`.

## النسخة التجريبية (apps/demo)

النسخة المنشورة على github.io موقوفة: متصفح Chrome وسمها «موقع خطِر» (تصنيف آلي خاطئ لصفحة جديدة على
استضافة مجانية بتذكر زاتكا وبتطلب أرقام ضريبية). بترجع على دومين المنتج.

تطبيق صغير بتجربة العميل: قائمة فواتير مصنّفة حسب العميل، إصدار فاتورة ضريبية لمنشأة أو مبسطة لفرد،
إشعار دائن أو مدين من صفحة الفاتورة، طباعة وحفظ PDF، وإرسال عبر واتساب. بيشتغل كله بالمتصفح بنفس كود
`packages/zatca`، وبيوقّع بشهادة زاتكا التجريبية المنشورة بحزمة الـ SDK. ما في إرسال لزاتكا، والمستندات ما إلها أي أثر ضريبي.
النشر يدوي من `.github/workflows/pages.yml`.

```bash
pnpm --filter @khatm/demo build   # → dist/site/index.html (الموقع) و dist/index.html (نسخة Artifact)
pnpm --filter @khatm/demo e2e     # Chromium: يصدر الأنواع الستة ويمررها على مدقّق زاتكا الرسمي
```

بالمتصفح، `node:crypto` بيتبدّل بـ `src/node-crypto-shim.ts` (SHA-256 وECDSA secp256k1 عبر مكتبات noble،
وقراءة الشهادة بمحلّل DER تبع المكتبة)، فالكود اللي بيبني ويوقّع هو نفسه بدون أي تعديل.

## قرارات تقنية مهمة

| الموضوع | القرار |
|---|---|
| التجزئة | حذف `UBLExtensions` و`cac:Signature` ومرجع QR **مع إبقاء المسافات حولها** ثم C14N 1.1 — مطابق لـ XSLT الـ SDK، ومختبَر على 19 عينة رسمية ومع libxml2 |
| التوقيع | ECDSA-SHA256 على **بايتات** تجزئة الفاتورة (مش على SignedInfo)؛ بصمة الشهادة وSignedProperties بصيغة base64(hex(sha256)) |
| QR | الوسم 4 = `PayableAmount` (المبلغ المستحق) مش `TaxInclusiveAmount` — بيختلفوا لما يكون في دفعة مقدمة |
| قالب الشهادة | sandbox: `TSTZATCA-Code-Signing` · simulation: `PREZATCA-Code-Signing` · production: `ZATCA-Code-Signing` |
| التسلسل | صف الجهاز يُقفل (`SELECT … FOR UPDATE`) طول معاملة الإصدار؛ اختبار 100 فاتورة متوازية → ICV من 1 لـ 100 بلا فجوة وسلسلة PIH سليمة |
| الحسابات | أعداد عشرية دقيقة (BigInt)، تقريب نصف لأعلى؛ ضريبة السطر تُقرّب لكل سطر وضريبة الفاتورة لكل فئة |
| حمايات القاعدة | triggers تمنع تعديل/حذف الفاتورة الصادرة، رجوع أو قفز العدّاد، وتعديل سجل التدقيق |
| الأسرار | مفاتيح الأجهزة وأسرار CSID مشفّرة AES-256-GCM بمفتاح رئيسي خارج القاعدة |
